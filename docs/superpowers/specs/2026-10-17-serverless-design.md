# keepMeUpdated — Serverless (GitHub Actions + static site) Design

Date: 2026-10-17
Status: Approved in chat; supersedes the server parts of `2026-10-17-keepmeupdated-design.md` (sections 2, 3 store, 4 scheduler, 5, 9)

## 1. Goal

Remove the Node/Express server and all local secrets. GitHub becomes the whole backend:
- **GitHub Actions** runs the daily gather and deploys.
- **The repository** stores the data as files.
- **GitHub Pages** hosts a static site.

News is kept for 30 days only, so there is no database.

### Success criteria
- No server process, no `.env`, no admin username/password anywhere in the repo or on disk.
- A scheduled workflow (03:00 UTC = 04:00 UK summer time) gathers, prunes items older than 30 days, commits, builds and
  deploys. It can also be started from the admin panel.
- The only secret is `GEMINI_API_KEY`, stored in GitHub Actions secrets. Without it the gather runs in fallback mode.
- The public site works from static JSON. The admin panel works entirely in the browser through the GitHub API, signed in
  with a fine-grained token that is never stored in the repo.
- Every existing feature keeps working, except: source "Test fetch" becomes a workflow dry run, and AI re-summarize
  becomes a workflow run.

## 2. Repository layout

```
content/posts.json      canonical posts (all statuses), committed — written by the gather and by the admin
content/state.json      { seen, runs, settings }, committed — written by the gather only
sources.md              news sources (unchanged format), committed — written by hand or by the admin
scripts/                was server/: gather pipeline + CLIs (no HTTP server)
  gather.ts             CLI: --mode gather | resummarize --post <id> | dry-run
  build-data.ts         CLI: content/ → public/data/ (site index, per-post files, site.json)
  content/files.ts      load/save content files, retention
  gather/*              fetchers, dedupe, ai, pipeline (unchanged logic)
shared/                 types + pure helpers used by scripts and the browser (sources-md, feed, slug)
public/data/            GENERATED at build (git-ignored): posts.json, p/<slug>.json, site.json
.github/workflows/      gather.yml, deploy.yml
```

Removed:
- `server/index.ts`, `app.ts`, `config.ts`;
- `api/*` (auth, sessions, rate limit, admin API);
- `scheduler.ts`, `store/json-store.ts`, `store/seed.ts`;
- `.env`, `.env.example`, `data/`, `proxy.conf.json`;
- the deps express, cookie-parser, express-rate-limit, node-cron, dotenv, supertest, concurrently and cross-env.

## 3. Data

```ts
// content/posts.json
Post[]                                    // same Post type as today
// content/state.json
{ version: 1, seen: Record<url, iso>, runs: Run[] /* last 50 */, settings: Settings }
// Settings gains retentionDays (default 30)
```

**Retention** runs at the start of every gather:
- posts whose `publishedAt ?? createdAt` is older than `retentionDays` are deleted;
- `seen` entries older than `retentionDays` are deleted;
- runs are capped at 50.

A post that still appears in a feed after deletion is not re-posted, because its URL is refreshed in `seen` each time it is
listed.

**Public data**, generated by `build-data`, published posts only:
- `public/data/posts.json`: `{ generatedAt, posts: PostSummary[] }`, newest first.
- `public/data/p/<slug>.json`: a full `Post`, with `bodyHtml` sanitized with the same allow-list as before.
- `public/data/site.json`: `{ repo: "owner/name", branch: "main", gatherWorkflow: "gather.yml", schedule: "0 3 * * *" }`.
  `repo` comes from `GITHUB_REPOSITORY`, or locally from `git remote get-url origin`.

## 4. Workflows

**`gather.yml`**
- Triggers:
  - `schedule: '0 3 * * *'`;
  - `workflow_dispatch` with inputs `mode` (`gather` | `resummarize` | `dry-run`, default `gather`) and `post_id`.
- `concurrency: gather`, no cancel. This replaces the in-process run lock.
- Permissions: `contents: write`, `pages: write`, `id-token: write`.
- Steps: checkout → setup-node 24 → `npm ci` → `npm run gather -- --mode … --post …`, with env `GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}`.
- The job summary gets the run log, and per-source counts for a dry run.
- If `content/` changed, commit as `github-actions[bot]`. A push rejected because main moved is retried with
  `git pull --rebase` up to 3 times; a real conflict fails the job, which shows on the Runs page.
- Then the reusable deploy runs (`uses: ./.github/workflows/deploy.yml`). This is needed because a push made with
  `GITHUB_TOKEN` does not trigger other workflows.

**`deploy.yml`**
- Triggers: `push` to main, `workflow_dispatch`, `workflow_call`.
- `npm ci` → `npm run build` (build-data + `ng build --base-href /<repo-name>/`) → copy `index.html` to `404.html` (SPA
  deep links) → `upload-pages-artifact` → `deploy-pages`.
- `concurrency: pages`.

## 5. Static site

- Home and the post page fetch `data/posts.json` and `data/p/<slug>.json`, as relative URLs resolved against the base href.
- Day grouping, the tag list, search, tag filter and "Load older days" run in the browser, on top of the one index file,
  using `shared/feed.ts` (moved from the server).
- No other public behaviour changes.

## 6. Admin (browser + GitHub API)

**Sign-in**
- Paste a fine-grained personal access token, scoped to this repository only, with these permissions: Contents read/write,
  Actions read/write, and Metadata read (automatic).
- The token is checked with `GET /repos/{repo}`: `permissions.push` must be true.
- It is stored in `sessionStorage`, or in `localStorage` when "Keep me signed in on this device" is ticked.
- Sign out clears both.
- A link opens GitHub's new-token page.

**Reads**
- `content/posts.json`, `content/state.json` and `sources.md` at the branch head, through the contents API with the raw
  media type.

**Writes**
- One file per change, through the Git Data API: blob → tree on the head commit → commit → fast-forward ref update.
- A change is a pure function (`text → text`). On a ref-update conflict, the file is re-read at the new head and the
  function re-applied, up to 3 attempts.
- Commit messages: `admin: update post "<title>"`, `admin: delete post …`, `admin: update sources`.

**Pages**
- **Posts:** list, publish/unpublish, delete, and the editor (Tiptap, unchanged) all read and write `content/posts.json`.
  Slugs are made unique against the loaded posts.
- **Sources:** reads and writes `sources.md` (parse and render moved to `shared/sources-md.ts`). "Test fetch" is removed;
  the Runs page has a "Dry run" button instead.
- **Runs:**
  - Status: last run's AI mode and the next scheduled time (03:00 UTC).
  - Buttons: "Run gather now" and "Dry run" (`workflow_dispatch`).
  - Live list from `GET /actions/workflows/gather.yml/runs`, with links to the GitHub logs.
  - Run history with each run's log from `state.json`.
- **Re-summarize:** dispatches `mode=resummarize, post_id`.
- After every commit, the UI says "Saved. The site updates in about 2 minutes."

**Login page:** fix the `.card` class collision with the story-card style, which is the cause of the spacing issue.
Redesign it with proper padding and spacing, a short explanation of the token and the steps to create one, and a "Keep me
signed in" option.

## 7. Security

- `GEMINI_API_KEY` exists only in Actions secrets.
- The admin token exists only in the admin's browser storage.
- The repo is public: everything committed is public news data.
- Public HTML is sanitized at build time, and Angular sanitizes it again at render.
- Admins can only do what their token allows on GitHub, so there's nothing to brute-force.

## 8. Setup the owner does (documented in the README)

1. Make the repository public (Settings → General → Danger zone).
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions → New repository secret: `GEMINI_API_KEY`.
4. Create a fine-grained token: Repository access is this repo only. Permissions: Contents read/write, Actions read/write.
   Keep it in a password manager and paste it on `/admin/login`.

## 9. Testing

- **Scripts (Vitest):**
  - content load/save and retention;
  - gather CLI modes with mocked fetch/AI (gather, resummarize, dry-run);
  - build-data output (published only, sanitized, site.json);
  - shared `sources-md` and feed helpers.
- **Web (Vitest + TestBed):**
  - GitHub client (read raw, commit flow, conflict retry, dispatch);
  - login (token validation);
  - home and post page on static JSON;
  - posts list, editor, sources and runs against a mocked repo client.
- **Workflows:** YAML parsed and checked structurally; the real run happens after the owner pushes and sets up Pages.
